# World behaviors and Lua

A behavior descriptor in `world/behaviors/` declares its identity, contract version,
Lua implementation, supported events, parameter types and relations. List it in
the map catalog's `behaviorCatalog`. Each object binds a descriptor and supplies
its own parameters and relationships. No Lua configuration table is required.

Implementations under `scripts/world_behaviors/` are excluded from recursive
RevScript loading. World loads only scripts referenced by the catalog, after the
normal script libraries and before loading the map. Registration outside the
descriptor's script, duplicate events and incompatible versions are rejected.
An invalid implementation prevents initial startup. A failed script reload leaves
the affected events unavailable and logs a diagnostic.

## Accessing configuration and instances

| API | Result |
| --- | --- |
| `World.get(id)` | Active declaration reference, or `nil` |
| `World.fromItem(item)` | Reference to that managed instance, or `nil` |
| `World.resolve(token)` | Reference guarded by identity, generation and script epoch |
| `object:getItem()` | Live item, or `nil` before publication/after removal |
| `object:getPosition()` | Effective position; anchors have no item |
| `object:getInitialItemId()` | Initially configured item type; `nil` for anchors |
| `object:token()` | Plain Lua table for deferred work, or `nil` without a live instance |
| `context:object()` | Source object during this invocation |
| `context:parameter(name)` | Typed, owned copy, with descriptor defaults applied |
| `context:relation(name)` | One reference, a list for multi-valued relations, or `nil` |
| `reference:getObject()` | Related object while its guarded identity remains valid |
| `reference:getPosition()` | Related position including the declared offset |

Defaults also apply within lists and nested records. Editing a returned Lua table
does not modify the runtime's configuration. Integers used as parameters must be
exactly representable by Lua's number type, in the range
`-9007199254740991..9007199254740991`. Positions use the normal Lua position API;
offsets are signed coordinate tables. Object-reference parameters use the same
reference API as relationships.

Contexts expire when their invocation returns or scripts reload. A removal
callback may still read the object's configuration during the notification;
`getItem()` returns `nil` once the item has left the live world. Save values or
tokens for deferred work, not the context or a borrowed item reference:

```lua
local token = context:object():token()
addEvent(function(reference)
	local object = World.resolve(reference)
	local item = object and object:getItem()
	if not item then
		return
	end
	-- Perform work only on this still-valid instance.
end, 1000, token)
```

Tokens contain decimal strings for the generation and epoch to avoid rounding
64-bit counters. Transformation, removal, stack changes and script reload retire
old tokens. They do not prolong item lifetime. Keep token contents unchanged.

## Events

Assign callbacks to `WorldBehavior(id, version)`, then call `register()`.
Every event declared by the descriptor must have an implementation. Callbacks
must return a boolean; errors, missing returns and unavailable callbacks deny the
event. The configured World handler consumes that object's event even on denial;
it cannot fall through to UID/AID, native action or container-opening handlers.
Events not assigned to World keep their existing dispatch.

| Event | Arguments after `context` |
| --- | --- |
| `onUse` | `player, item, fromPosition, target, toPosition, isHotkey` |
| `onStepIn`, `onStepOut` | `creature, item, position, fromPosition` |
| `onAddItem`, `onRemoveItem` | `movingItem, tileItem, position` |

Movement events retain the server's notification semantics. Returning `false`
stops further dispatch; it does not reverse movement already performed. A gameplay
rule that needs to return a creature must explicitly move it to its previous or
another permitted position.

The implementation at
`data-otservbr-global/scripts/world_behaviors/quest_gated_door.lua` demonstrates
level/storage checks and a related door. Its descriptor defines all configurable
values, so another quest can reuse it without C++ changes. Door closing or a timer
requires a corresponding behavior; the example only opens the door.

Lua API reference/stubs are generated by the existing native documentation
generator from the binding docblocks. Run the maintained docs-only entry point
with a compatible artifact; generating documentation does not require a running
game server.
